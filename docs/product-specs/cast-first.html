OGS app rework · product spec · Oct 2026

Cast first. One stream all evening. The phone is the controller.

Open OGS, cast to the TV, and the TV becomes a game console. Games launch inside that one stream, so switching never recasts.

Cast

The app sends LOAD_VIEW with the launcher URL, not a game URL. The receiver never changes page again until the evening ends.

Switch

The launcher swaps the framed game. The old game gets ogs:suspend, reports its resume point, and is unloaded. No new stream.

Kids

The session tells each paired iPad which game and role, with a signed join URL. The iPad's WebView navigates; the child does nothing.

For game authors

Still config, not code

Games stop owning casting. A game's TV page only has to be frameable and answer three optional messages.

{
  "appId": "rocket-crew",
  "name": "Rocket Crew",
  "shape": "couch",
  "tvUrl":   "https://rocket-crew.example/tv",        // framed by the launcher; allow frame-ancestors opengame.org, autoplay
  "joinUrl": "https://rocket-crew.example/join",      // kid and grown-up devices land here with a signed token
  "roles": [{ "id": "captain", "audience": "grownup" }, { "id": "fixer", "audience": "kid" }],
  "art": { "tv": "/key.jpg", "safe": { "scale": 1.17, "ox": 50, "oy": 100 } },
  "suspend": true                                     // optional: answers ogs:suspend with a resume point
}

Decide

Open questions

Default tabAfter casting, does the controller open on Remote or Games? Both stay one tap apart.
Who's playing, every time?Or only when the roster changed since last time (one tap fewer on a normal night).
Frame or navigate?Framing keeps the launcher alive and swaps instantly; it needs each game's TV page to allow framing and autoplay. Navigating the top page is simpler but reloads.
Who sends pushesOGS from Tier 2 instance reports, or each game via notification-kit?
Save keysSaves keyed by the player's token are callable from the browser: needs a security review.
