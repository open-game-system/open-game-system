## 0. One push reaches the owner's iPhone (before any code)

Nothing shows the app's Expo path has ever delivered. Needs the owner (Apple login):

- EAS push credentials for iOS (`eas credentials`, APNs key for `org.opengame.app`).
- The owner's phone runs a build that registers (`initializePushNotifications` in `apps/mobile/app/_layout.tsx`)
  and its `devices` row has an Expo token.
- One send through Expo (ask the owner before sending). Done when the banner shows and a tap opens the app.

## 1. API: handles, surfaces, consent, send (app pipe)

- Schema (`services/api/schema.sql` + `docs/architecture.md`): `push_handles (id, app_id, created_at)`,
  `push_surfaces (handle_id, kind ogs|web, profile_id?, endpoint?, p256dh?, auth?, last_active_at)`,
  `api_keys` stored hashed with a prefix and a scope (today: plaintext primary key).
- Routes (`services/api/src/routes/`): `POST /games/:appId/push-handles` (app, profile auth: consent →
  handle), `POST /games/:appId/notifications` (game API key), Settings grant list/revoke for the app.
- Delivery: last-active surface, fall through on gone, never a kid profile, `tag` → Expo `collapseId`/thread.
- Schemas in `ogs-protocol` (payload, results, bridge events), parsed at the boundary.
- Remove `/api/v1/notifications/send`, `DeviceTokenPayloadSchema`, the device-token JWT from registration.
- Script: `pnpm --filter @open-game-system/api issue-key <appId>` (prints once).
- Proof: Worker integration tests for every scenario in game-push.feature's Sending section (fake Expo).

## 2. App and profile-kit

- profile-kit: `requestOgsNotifications`, `onOgsNotification` over a new bridge store; docs reference
  (`apps/docs/content/profile-kit.md`, drift test) and contract §9.
- App: consent sheet; Settings → Notifications per game; foreground handler (swallow when the game's WebView
  for that appId is in front and `whenOpen` is `deliver`, else the app's banner); taps open `url`.
- Links: catalogue-driven routing replaces `services/deep-links.ts`'s hard-coded list; `opengame.org/play/*` in
  the AASA file and an Android intent filter (native build); fix `/play` on opengame.org's association file.
- Proof: Jest for the handler and routing; e2e with a fake bridge; then the owner's phone (step 0 build).

## 3. Pocket Draft (first game, app pipe)

- First: seam tests on the trigger transitions (`room.rules.ts` `lockInFor`/`passFor`/`applyLock`,
  `draftDone`, `markReady`, `completesSeating`), since the game is lightly tested.
- Then: the spec's `Notifier` seam (`docs/product-specs/gm-game.md:207`): seat stores its handle; consent asked
  after the first lock; "this round is waiting on you" once per stalled round, 10 min after the round stalls,
  on the existing DO alarm; skip connected seats.
- Proof: seam tests with a stub OGS endpoint; a real two-phone round on the owner's devices.

## 4. Web push and Codebreakers "Play over days"

- API: per-game VAPID keys (encrypted in D1 under one secret), `GET /games/:appId/push-key`,
  `POST /games/:appId/push-subscriptions` (origin = `startUrl` origin), Web Push encryption + VAPID JWT on Web
  Crypto (check first whether an existing library runs on Workers).
- New package `notification-kit-web`: `subscribeOgsPush`, re-subscribe on key change, `sw.js` (swallow when a
  focused window exists; verify Safari's rule on an iPad first).
- `notification-kit-server`: thin Zod-parsed client of the send endpoint.
- Codebreakers (its own spec section and `.feature` first): persisted rooms (DO storage), phone-only play,
  `tv: "optional"`, one reminder after 24 h idle, expiry at 7 days, handles per seat, pushes from `GIVE_CLUE`
  and `passTurn`, `reportOgsSitting({ status: "waiting", yourTurn })`, manifest + `sw.js`.
- Proof: an async game played over a day across an iPhone in the OGS app, an iPad Home Screen PWA and an
  Android browser.

## 5. Docs site

`apps/docs/content/`: a Notifications page (Codebreakers as the worked example), quickstart step 13, testing
(fake consent store, stub send endpoint), rules (no kids, one push per handoff, no streak nags).
