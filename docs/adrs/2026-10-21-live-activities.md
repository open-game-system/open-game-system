# Live Activities live in the shell: a custom config plugin, an in-package Expo module, couch-session pushes

**Date:** 2026-10-21 · **Status:** Accepted (ships dark)

## Context

While a phone is the controller for a game on the TV, we want an iOS Live Activity (lock screen plus
Dynamic Island) that returns to the controller when tapped, like Netflix's game controller. Every OGS
app should get it: the OGS app and each game's own app built on `@open-game-system/shell`.

## Decision

- **The widget extension is generated by the shell's own config plugin** (`withShellLiveActivity`),
  not by @bacons/apple-targets. apple-targets expects the target sources in the app's own `targets/`
  folder, but ours ship inside a package. The plugin copies `packages/shell/ios/widget` and
  `ios/shared` into `ios/OgsLiveActivity` and adds the target with the `xcode` library at every
  prebuild. Nothing in `ios/` is hand-edited.
- **The ActivityKit bridge is an Expo module inside the shell package** (`expo-module.config.json`,
  pod `OgsShell`). The shell used to be JS-only. Now a change under `packages/shell/ios` changes a
  consuming app's native fingerprint and ships as a new build. A JS change still ships over the air.
- **Status comes from the existing bridge.** The game's `INSTANCE_REPORT` on the `ogs` store (already
  Zod-validated) supplies it, so there is no new game contract. Locally, the couch session drives
  start, relabel and end.
- **Remote updates key on the couch session.** Phones register activity tokens under it. The
  CouchSession DO pushes `liveactivity` update and end events when the session's game, label or cast
  changes. The OGS app sends with its own APNs key (secrets). A white-label app sends with its uploaded
  key (ADR 2026-10-18-multi-tenant-push).
- **Three flags, all off:** the shell config's `liveActivities`, the OGS app's `OGS_LIVE_ACTIVITIES=1`,
  and the Worker's `LIVE_ACTIVITIES=on`.

## Consequences

- The extension's bundle id (`<bundleId>.OgsLiveActivity`) and app group (`group.<bundleId>.ogs`) have
  to be provisioned. EAS should do it from `extra.eas.build.experimental.ios.appExtensions`
  (unverified).
- Remote and local updates can race. Each content state carries `updatedAt`, and the later write wins
  on the lock screen.
- Push-to-start tokens reach JS but aren't stored. Starting an activity from the server is a
  follow-up.
