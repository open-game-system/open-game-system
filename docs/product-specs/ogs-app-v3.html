OGS app rework · product spec v3 · Oct 2026

Your games on any screen. Cast when you want the TV.

OGS opens on what needs you, or your library. Play on the phone, or cast once and the TV becomes a game console for the evening: every game launches inside that one stream.

App structure

Three tabs: TV · Playing · Library (always all three)

TV is a big Cast button until you cast, then the remote. Playing is everything in flight, with the live game pinned on top. Library is your games, plus Add games. A game screen slides over everything and swipes away from the left edge, as today.

Opens on

Playing when something needs you (a turn, a game night tonight, a live game). Library otherwise.

Getting back in

Three doors to the same place: the pinned card in Playing, the return pill on any tab, or a push. A push is a shortcut, never the only way.

When nothing's going

Playing is always there. Empty, it suggests what to start now (couch games for the TV, Hearthisle on phones, a duel to start) and what you played last. Cast with nothing running: "On the TV · your games", and a tap sends a pick to the TV.

Adding games

Games are free web games, so there is no Shop tab: "+ Add games" in Library browses the catalogue, and Add by link takes any OGS game URL.

Cast

The app sends LOAD_VIEW with the launcher URL, never a game URL. The receiver keeps that page all evening.

Launch

A tap in the library and a select on the TV both send game.start. The session is the one source of truth.

Switch

The launcher swaps the framed game. The old one gets ogs:suspend and reports its resume point. No new stream.

Session states

Not cast is a whole app, not an error

For game authors

Still config, not code

Games stop owning casting. A manifest gets a game into Add games and onto the TV; three optional messages make it pause cleanly.

{
  "appId": "rocket-crew",
  "name": "Rocket Crew",
  "shape": "couch",                                     // couch | live | async
  "tv": "required",                                     // none | optional | required
  "tvUrl":   "https://rocket-crew.example/tv",          // framed by the launcher: allow frame-ancestors opengame.org + autoplay
  "joinUrl": "https://rocket-crew.example/join",        // phones and kid iPads land here with a signed token
  "roles": [{ "id": "captain", "audience": "grownup" }, { "id": "fixer", "audience": "kid" }],
  "art": { "tv": "/key.jpg", "safe": { "scale": 1.17, "ox": 50, "oy": 100 } },
  "shop": { "ages": "4+", "minutes": [8, 12], "players": "1 grown-up + 1–2 kids" },
  "suspend": true                                       // optional: answers ogs:suspend with a resume point
}

Verification

How we know it works: four layers, one scenario list

Every storyboard step above becomes a scenario in docs/acceptance/. Each layer proves the part it can see; the e2e framework drives one device per test, so cross-device truth lives in the session tests.

1 · Session seam testsThe cross-device truthCouchSession on vitest-pool-workers with fake phone, launcher and iPad clients over real WebSockets. Proves: one game.start from either screen, swipe back = home + resume point, iPads get follow, 0 recasts, re-cast resumes at Mission 6.
2 · e2e per surfacePhone, TV launcher, kid iPadThe e2e framework (tester.army): iOS simulator with the Expo dev build, the launcher as a web target, an iPad simulator. Locators where exact, cached agent.act / agent.assert where not. A project tool plays the other screens through the session's test API.
3 · Visual checksThe prototype's rigScreen sheets and checks from design/: 44 pt targets, AA contrast, 0 words on kid screens, TV text ≥ 24 px, no overlaps. The prototype's flows are the reference picture for each scenario.
4 · Real hardwareThe living roomCast to the real Chromecast and record the stream; av-verdict fails black or frozen video. One swap on the real iPads per release.
